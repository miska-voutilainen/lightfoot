# Working on Lightfoot

Instructions for AI coding agents (and anyone else) changing this repository. Lightfoot is a local proxy between a coding agent and the model API that condenses what each turn re-sends. It rewrites live requests, so the rules below are what keep it safe.

Read [docs/architecture.md](docs/architecture.md) for how it works and [docs/development.md](docs/development.md) for the layout and commands.

---

## Rules every change keeps

These are enforced by the tests; a change that needs to break one needs the user's agreement first. Details in [CONTRIBUTING.md](CONTRIBUTING.md#rules-every-change-keeps).

1. **Only tool output and validated prunes change** in a request. Everything else stays byte-identical.
2. **Rewrites are frozen:** stored once and replayed byte for byte on every later request.
3. **Unseen content is the only free edit.** Anything the model has already seen is a history edit.
4. **History edits are gated** by cache economics, a verified adapter and the thinking-prefix check, and prunes happen only at a new user prompt.
5. **Failures drop new rewrites only.** Stored rewrites keep being replayed.

---

## Never without the user's approval

- **Anything that calls a real model API:** `bench/`, `lightfoot eval run`, live probes. It spends the user's money or subscription limits. Mock-API checks (`scripts/agent_check.py`, `scripts/drift_check.py`) are free and fine.
- **Commit or publish `notes/`.** It holds private plans and is git-ignored.
- **Publish a release** or change anything on PyPI.

## Before you finish

```sh
pytest                                              # on a sandboxed Windows shell: add --basetemp=<a writable folder>
ruff check lightfoot tests scripts bench
ruff format --check lightfoot tests scripts bench
```

Add a line to `CHANGELOG.md` under "Unreleased" for anything a user would notice.

## Common updates

### A provider ships a new model or changes prices

- **Edit `lightfoot/data/models.toml`, not the code.** It holds the prices (as listed on each provider's price page), their sources and dates, the fallback model per family, the models that support model-written summaries, and the beta header names. Its comments say what each field means.
- Take every number from the provider's own price or docs page, and update the `checked` date for what you read. `lightfoot doctor` warns when the newest date is more than 60 days old.
- A malformed entry fails at import with its name; `tests/test_models_data.py` checks the file.
- What a provider allows (cache model, history edits, credentials) steers behaviour, so it stays in code: `lightfoot/providers.py`.

### An agent ships a new version

1. Run `python scripts/agent_check.py` (Codex CLI, opencode, Aider, Gemini CLI) or `python scripts/drift_check.py` (Claude Code). Both are free.
2. If an agent's request shapes changed, review them and accept with `--update` on the same script. A new tool name usually means step 3.
3. If the agent renamed or added tools, update its profile in `lightfoot/profiles.py`. `lightfoot doctor` lists the tool names each profile didn't recognise in recent sessions.
4. If `python scripts/hook_watch.py` reports a new hook output field, check whether hook mode is now possible for that agent (its docstring says how).
5. Update the evidence in `lightfoot/support.py`. A level change goes in the README's agent table too; `tests/test_support.py` checks they agree.

### Adding an agent

Follow [CONTRIBUTING.md](CONTRIBUTING.md#adding-an-agent): a profile, an adapter only for a new API format, tests from the agent's real request shapes, and an entry in `scripts/agent_check.py`.

## Style

- **Code:** match the surrounding code. Every public module, class and function has a docstring (ruff enforces it); comments explain why, not what.
- **Docs:**
  - "Lightfoot" is capitalised in prose; lowercase in commands, paths and the package name.
  - No arrow symbols: write `->` or `>`. No emojis.
  - "Mock", never "fake", for test doubles.
  - Only Markdown that renders everywhere: no `> [!NOTE]` alerts, no Mermaid.
  - Diagrams are generated by `scripts/docs_assets.py`; edit the code, never the SVGs.
  - A measured number names what was measured; an illustration says it is one.
- **Git:** work on a typed branch (`docs/…`, `feat/…`, `fix/…`), merge into `main` with `--no-ff`. Short conventional commit messages. Scan the staged diff for secrets before every commit.
